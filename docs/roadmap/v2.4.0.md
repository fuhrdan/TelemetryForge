# v2.4.0 Delivered Scope

TelemetryForge v2.4.0 adds cryptographically verifiable lineage to the Durable Edge without changing the v2.2 durability boundary or v2.3 route-ownership semantics.

## Delivered

- WAL record format v2 with previous-record and current-record SHA-256 hashes;
- backward-readable v1 WAL upgrade anchoring;
- Merkle roots for closed WAL segments;
- Ed25519-signed `.tfseal` segment attestations;
- chained previous-segment roots;
- signer key IDs and embedded verification keys;
- persistent local key generation plus explicit production key paths;
- fail-closed signer mismatch when historical seals already exist;
- seal retention after delivered WAL compaction;
- lineage state in `/edge/status`;
- `telemetryctl audit keygen` and `telemetryctl audit verify`;
- optional trusted-public-key identity verification;
- cryptographic lineage tests and operational proof harness;
- ADR 0055 and operator documentation.

## Semantics

A successful v2.4 edge acceptance still means the v2.1/v2.2 durability contract succeeded. Cryptographic lineage adds evidence about ordering and tamper resistance; it does not replace replication, destination acknowledgement, or retention policy.

## Deferred

- authenticated signing-key rotation/transition records;
- hardware-backed HSM/KMS signing provider interfaces;
- remote transparency-log publication;
- cross-organization witness signatures;
- inclusion-proof API for individual historical events.

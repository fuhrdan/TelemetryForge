# v1.3.0 Delivered Scope

**Theme:** Telemetry Router and destination failure isolation.

## Delivered

- versioned routing JSON
- tenant/source/type/severity/tag matching
- multi-rule fan-out with destination deduplication
- unmatched-event fallback destination
- Kafka destinations
- HTTP/webhook destinations
- secret-backed HTTP bearer tokens
- durable PostgreSQL routing outbox
- independent router service
- per-destination concurrency lanes
- bounded exponential retry
- delivery leasing / crash recovery
- per-destination DLQ
- terminal failure fallback destination
- candidate shadow routing with no candidate I/O
- destination health/queue state
- routing API/CLI/dashboard surfaces
- Docker Compose and Kubernetes router deployment
- Prometheus routing outcome metric

## Explicit non-goals

v1.3.0 is **not** the final connector SDK.

The broader connector/plugin abstraction remains planned for v1.8.0. The two
v1.3 destination types are enough to establish routing semantics and failure
isolation without prematurely stabilizing a third-party extension API.

v1.3.0 also does not claim exactly-once delivery to external backends.
Destination delivery is at-least-once; event IDs/idempotency headers support
backend deduplication when the backend can provide it.

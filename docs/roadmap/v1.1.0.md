# v1.1.0 Delivered Scope

**Theme:** Schema Intelligence.

## Delivered

- tenant-scoped schema registry
- application `schema_version` history
- optional OpenTelemetry `schema_url`
- deterministic field/type fingerprints with no raw values
- bounded payload discovery
- accumulated registry field cap (2,048 unique paths per schema version)
- idempotent per-event observations
- guarded schema-observation ledger pruning
- additive drift findings
- same-version type conflict detection
- inferred-required missing-field detection
- version-to-version compatibility diff
- focused OpenTelemetry semantic-convention awareness
- legacy semantic attribute warnings
- fail-open worker integration by default
- schema API / CLI / dashboard
- deterministic schema demo

## Deliberately not delivered

v1.1 does not:

- block ingestion based on schema drift;
- claim to implement every upstream OpenTelemetry semantic convention;
- automatically rewrite legacy semantic attributes;
- infer required fields from a single event;
- distribute schema policy independently of PostgreSQL;
- automatically promote a new application schema version.

Those boundaries keep the release useful without making the registry a new
availability or false-positive risk.

## Acceptance criteria

- a retried Kafka event counts once in schema observations;
- schema state is tenant-scoped;
- a type change under the same declared version is breaking drift;
- sparse fields do not become required before the observation floor;
- an established required field disappearing is breaking drift;
- legacy semantic attributes produce a warning/replacement hint;
- schema registry dependency failure is fail-open by default;
- schema drift never silently mutates the telemetry event;
- accumulated schema state remains bounded under dynamic field-name generation;
- observation-ledger pruning preserves registry and drift history.

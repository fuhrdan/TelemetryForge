# v0.9.0 Delivered Scope

**Theme:** Incident Replay, cost simulation, self-observability, and measured
performance methodology.

## Incident Replay — delivered

- replay frozen incident events through normalization/current/candidate policy
- no normal production side effects by default
- explicit replay run identifier
- compact per-event effect results
- active/shadow effect counters
- `telemetryctl incident replay`
- isolated opt-in `telemetry.replay*` publication
- library-level production-topic rejection
- dashboard/API replay history

## Telemetry Cost Simulator — delivered

- exact frozen-sample series comparison
- canonical JSON sample byte comparison
- active/candidate policy comparison
- changed-event counts
- linear 30-day volume projection
- optional operator-supplied pricing model
- no default/vendor-dollar claims
- dashboard/API cost history

## Self-observability — delivered

- OpenTelemetry gateway/worker instrumentation
- W3C Trace Context propagation through Kafka
- Prometheus gateway/worker metrics
- broker-derived Kafka consumer lag
- worker queue depth/capacity
- retry/DLQ counters
- HTTP request rate/latency by route pattern
- worker processing/stage traces
- Prometheus + Grafana + Tempo + Collector local stack

## Load testing — delivered methodology

- checked-in k6 smoke scenario
- sustained-ingestion scenario
- bounded-backpressure scenario
- documented environment/result checklist
- CI syntax/option inspection

## Deliberately deferred

The original planning notes also considered additional metrics and a
browser/SSE-specific load scenario.

These are not falsely claimed as v0.9 deliverables:

- dedicated policy finding/quarantine Prometheus counters
- dedicated SSE client-count/poll-latency metrics
- explicit database write/query latency metrics
- full browser/dashboard/SSE k6 test
- published benchmark result artifact

The existing worker stage traces and HTTP metrics make many of these paths
visible, but v0.9 does not label them as dedicated metrics when they are not.

A benchmark result is also deferred until a representative dependency-backed
environment can run the complete stack and preserve its hardware/configuration
evidence.

## Acceptance criteria

- replay cannot publish to production ingest topics
- policy replay can evaluate active/shadow safely
- cost simulation cannot invent pricing
- HTTP Prometheus metrics use route patterns, not raw IDs
- Kafka lag comes from broker/group offsets
- backpressure can be observed through queue depth plus broker lag
- no benchmark claim without reproducible methodology and results

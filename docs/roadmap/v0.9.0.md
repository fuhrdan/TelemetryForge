# v0.9.0 Development Plan

**Theme:** Incident Replay, cost simulation, self-observability, and measured
performance.

## Incident Replay

- replay frozen incident events through current or candidate policy
- no production side effects by default
- explicit replay run identifier
- compare old/new findings and incident outcomes
- `telemetryctl incident replay`
- dashboard replay history

## Telemetry Cost Simulator

- estimate series/storage impact from cardinality findings
- compare active and candidate policy
- show expected retained/dropped dimensions
- avoid claiming vendor-dollar savings without configured pricing inputs

## Self-observability

- OpenTelemetry instrumentation
- Prometheus metrics
- broker-derived Kafka consumer lag
- worker queue depth
- retry/DLQ counters
- policy finding/quarantine counters
- SSE client count / poll latency
- database write/query latency

## Load testing

- checked-in k6 scenarios
- documented hardware/container settings
- ingestion throughput test
- sustained worker/backpressure test
- SSE/dashboard test
- reproducible results artifact

## Acceptance criteria

- no benchmark claim without checked-in methodology/results
- replay cannot publish to the production ingest topic by accident
- policy replay can use shadow mode safely
- operational metrics explain whether a bottleneck is gateway, Kafka, worker,
  policy, or database
